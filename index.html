代理对接文档

兑换接口供代理的服务器调用，用于查询卡密、核对买家账号、提交兑换和查询订单结果。买家在你自己的页面上操作，不需要访问我们的网站。

接口地址
https://recharge.chongplus.store/api/open/v1
认证
Authorization: Bearer <API 密钥>
格式
HTTPS，JSON（UTF-8），服务器之间调用
版本
v1 · 2026-10-17 修订（更新记录）

1. 概述

接口共 6 个，都需要 API 密钥。完成一次兑换按顺序调用其中 4 个；GET /ping 用于联调，POST /orders/lookup 用于找回订单。

方法与路径用途卡密
GET /ping验证密钥，查看来源 IP 和限额不涉及
POST /cdk/query查询卡密的套餐和状态不消耗
POST /redeem/verify核对买家账号，取得核对票据不消耗
POST /redeem提交兑换，取得订单号锁定
GET /orders/{order_no}查询订单状态和结果不涉及
POST /orders/lookup按卡密找回订单不涉及

另附 OpenAPI 3.0 描述文件 openapi.json，可以导入 Apifox、Postman 等工具，其中的字段、取值和错误码与本文档一致。

2. 兑换流程

  1. 查询卡密（可选）

    买家粘贴卡密后调用 POST /cdk/query，得到套餐和卡密状态。不消耗卡密。

  2. 核对账号

    买家提交 ChatGPT 账号的 Session 后调用 POST /redeem/verify。耗时约 10 秒，通过后得到核对票据 ticket，10 分钟内有效。

  3. 提交兑换

    买家确认后调用 POST /redeem，传入 ticket 和你生成的幂等号 idempotency_key，得到订单号 order_no。卡密从这一步开始锁定。

  4. 查询结果

    按返回的 poll_after 秒数轮询 GET /orders/{order_no}，直到 status 为 succeeded（已开通）或 failed（失败），通常需要 1–3 分钟。

注意

请求超时或没有收到响应时，用同一个 idempotency_key 和同一张 ticket 重发，或者调用 POST /orders/lookup 找回订单，不会重复兑换。不要换新的幂等号，也不要重新核对后再提交。完整规则见 重试规则。

3. 接入准备

开通时我们会提供以下信息：

项目说明
接口地址https://recharge.chongplus.store/api/open/v1，下文写作 {BASE}。
API 密钥cpa_ 开头，共 47 个字符。只在创建时显示一次，遗失后需要停用并重新申请。
来源 IP你的服务器出口 IP 或 IP 段。登记后，这把密钥只接受来自这些地址的请求。调用 GET /ping 可以看到接口识别到的来源 IP；请求因来源 IP 被拒绝时，ip_not_allowed 的 error.details.ip 也是这个地址。

警告

  • 密钥只保存在服务器端（环境变量或密钥管理服务），不要写进网页、App 或任何前端代码，也不要发到聊天群或工单里。
  • 接口只接受服务器之间的调用，不支持浏览器直接请求（不放行跨域请求）。
  • 只使用 https://。如果曾经用 http:// 发送过密钥，按已泄露处理：联系我们停用并更换。
  • 买家的 Session 等同于账号的登录凭证，只在本次请求中使用，不要保存，不要写进日志。
  • 怀疑密钥泄露时，联系我们停用，停用立即生效。
  • 用错误的密钥或从未登记的 IP 反复请求，来源 IP 会被临时封锁 10 分钟。

使用约定

使用本接口即表示同意以下约定：

  • 本接口只提供兑换能力，买家使用的页面、文案和样式由你自行设计制作。
  • 不得复制、仿制或套用我们网站的页面、样式、图片、视频和教程；不得用 iframe 嵌入我们的网站，也不得用自己的域名转发（镜像）我们的网站。
  • 失败的订单只能由买家本人发起重试，你的程序不得自动重新提交，原因见 失败后重新提交。
  • 密钥只供你自己的系统使用，不得转借或转卖。
  • 订单结果以本接口的返回为准。
  • 违反以上任何一条，我们将停用密钥。

4. 通用约定

请求

  • HTTPS，JSON（UTF-8）。POST 请求带 Content-Type: application/json，请求体不超过 128 KB。
  • 认证：每个请求带 Authorization: Bearer <API 密钥>。
  • User-Agent 填写你自己系统的名称，例如 my-shop/1.0。部分语言和库的默认值会被网关拒绝，例如 Python 的 urllib 和 pycurl、Java 8 及更早版本、Perl 的 LWP。被拒绝时返回 HTTP 403，响应只有一行纯文本 error code: 1010（不是 JSON），请求没有到达接口。
  • 超时时间设为 60 秒以上，核对账号一步约需 10 秒。

响应

所有响应都是 JSON。成功时 HTTP 200，ok 为 true：

{
  "ok": true,
  "data": { ... },
  "trace_id": "9F2A41C07B"
}

失败时 ok 为 false，HTTP 状态码见下表：

{
  "ok": false,
  "error": {
    "code": "cdk_used",
    "message": "卡密已兑换或已使用",
    "retryable": false,
    "cdk_state": "used",
    "details": { "order_no": "OD3F9A1C07B2D4E5" }
  },
  "trace_id": "9F2A41C07B"
}
字段类型说明
okboolean请求是否成功。
dataobject成功时的返回内容，各接口不同。
error.codestring错误码，取值固定，程序按它判断。全部取值见 错误码。
error.messagestring面向买家的中文说明，可以直接展示；需要自定义文案时按 error.code 判断。
error.retryableboolean同样的操作稍后能否再试。具体怎样重试以各接口的说明为准，有的需要重新核对账号。
error.retry_afterinteger建议等待的秒数，同时放在 Retry-After 响应头中。只在需要等待的错误中出现。
error.cdk_statestring这一步之后卡密的状态，取值见 卡密状态。不一定出现。
error.detailsobject附加信息，不一定出现：order_no 表示卡密已被你这把密钥提交过，可以用 GET /orders/{order_no} 查询；ip 只在 ip_not_allowed 时出现，是接口识别到的来源 IP。
trace_idstring每个响应都有。联系我们排查问题时请提供。

HTTP 状态码

状态码含义
200成功（ok 为 true）。
400请求格式错误（bad_request），或 Session 格式错误（session_format）。
401 / 403密钥无效或已停用（invalid_key）/ 来源 IP 不在登记名单中（ip_not_allowed）。
404接口、核对票据或订单不存在。
409当前状态不允许这个操作，例如卡密已使用、核对已过期、票据已提交过、账号需要等待。
422请求格式正确，但内容未通过校验，例如卡密无效、Session 已失效。
429请求过于频繁、同时处理的订单过多或系统繁忙，按 Retry-After 等待后重试。
500 / 503服务暂时无法处理，稍后重试。

限额

  • 每把密钥有两个上限：每分钟请求数和同时处理中的订单数，默认 60 次/分钟和 5 单，以 GET /ping 返回的 limits 为准，需要调整请联系我们。超出时返回 429（rate_limited 或 too_many_inflight）。
  • 高峰期或请求过密时，可能临时返回 429 busy，按 Retry-After 稍后重试即可，与密钥本身无关。

时间格式

所有时间都是 RFC 3339 格式的 UTC 时间，例如 2026-10-05T09:00:00Z。

5. 接口

下文示例中，{BASE} 是接口地址，$KEY 是你的密钥，卡密用 XXXXXXXXXXXX-XXXXXXXXXXXX-XXXXXXXXXXXX 代替。

GET /ping

GET/ping联调

验证密钥是否有效，返回密钥名称、接口识别到的来源 IP 和限额。登记来源 IP 时以这里返回的 ip 为准。没有请求体。

响应字段

字段类型说明
namestring密钥名称。
ipstring接口识别到的来源 IP。
server_timestring服务器当前时间。
limits.rate_per_mininteger每分钟请求上限。
limits.max_inflightinteger同时处理中的订单上限。

示例

curl {BASE}/ping -H "Authorization: Bearer $KEY" -H "User-Agent: my-shop/1.0"
{
  "ok": true,
  "data": {
    "name": "代理甲",
    "ip": "203.0.113.10",
    "server_time": "2026-10-05T09:00:00Z",
    "limits": { "rate_per_min": 60, "max_inflight": 5 }
  },
  "trace_id": "9F2A41C07B"
}

可能的错误

invalid_key、ip_not_allowed、too_many_failures、rate_limited、service_disabled，说明见 错误码。

POST /cdk/query

POST/cdk/query只读不消耗卡密

查询卡密对应的套餐和当前状态，不需要买家的账号信息。同一张卡密 60 秒内重复查询，可能返回缓存结果。

如果这张卡密已经由你这把密钥提交过订单：订单还在处理时返回 cdk_not_usable，已兑换成功时返回 cdk_used，两种情况都在 error.details.order_no 中给出订单号。

请求字段

字段类型必填说明
cdkstring是卡密。不区分大小写，首尾空格会被忽略。

响应字段

字段类型说明
planstring套餐代号，取值见下表。
plan_namestring套餐名称，可以直接展示。
cdk_statestring卡密状态，见 卡密状态。
planplan_name
goGo
plusPlus
pro-5xPro 5x
pro-20xPro 20x
pro-maxPro Max
otherChatGPT 套餐。以后新增的套餐会先使用这个取值，程序不需要因此修改。

示例

curl -X POST {BASE}/cdk/query -H "Authorization: Bearer $KEY" -H "User-Agent: my-shop/1.0" \
  -H "Content-Type: application/json" \
  -d '{"cdk":"XXXXXXXXXXXX-XXXXXXXXXXXX-XXXXXXXXXXXX"}'
{
  "ok": true,
  "data": { "plan": "pro-5x", "plan_name": "Pro 5x", "cdk_state": "available" },
  "trace_id": "9F2A41C07B"
}

可能的错误

错误码场景处理
cdk_invalid卡密格式不对或不存在请买家核对卡密。
cdk_used卡密已兑换error.details.order_no 有值时，是你这把密钥提交的订单，查询该订单。
cdk_not_usable暂时不能使用：已停用、已冻结或正在处理error.details.order_no 有值时，是你这把密钥提交的订单仍在处理，查询该订单；否则请买家联系你，必要时联系我们。
busy / service_unavailable / try_later系统繁忙或暂时不可用稍后重试。

POST /redeem/verify

POST/redeem/verify约 10 秒不消耗卡密

核对买家的账号能否兑换这张卡密，通过后返回核对票据 ticket。这一步约需 10 秒，请把超时设为 60 秒以上。

请求字段

字段类型必填说明
cdkstring是卡密。
sessionstring / object是买家的整页 Session，可以是字符串，也可以是 JSON 对象。

提示

获取 Session：让买家在已登录 ChatGPT 的浏览器中打开 https://chatgpt.com/api/auth/session，复制页面上的全部内容（以 { 开头，包含 accessToken）。只复制其中的 token，或者提供邮箱和密码，都会返回 session_format。

示例

curl -X POST {BASE}/redeem/verify -H "Authorization: Bearer $KEY" -H "User-Agent: my-shop/1.0" \
  -H "Content-Type: application/json" \
  -d '{"cdk":"XXXXXXXXXXXX-XXXXXXXXXXXX-XXXXXXXXXXXX","session":"{\"user\":{...},\"accessToken\":\"...\"}"}'

账号可以兑换：

{

  "data": {

    "ticket": "tk_3f9a1c07b2d4e5a6b7c8d9e0f1a2b3c4",
    "expires_at": "2026-10-05T09:10:00Z",
    "plan": "pro-5x",

{

  "data": {
    "eligible": false,
    "reason": "account_has_plan",

字段类型说明

account.current_planstring账号当前的套餐：free，或者 plan 的取值之一。
account.current_plan_namestring账号当前套餐的名称。
account.has_active_planboolean账号当前是否有生效中的套餐。为 true 时 eligible 为 false。

可能的错误

错误码场景处理
session_formatSession 不是整页内容，缺少 accessToken 等请买家按上面的方法重新复制。
session_invalid账号登录已失效请买家重新登录后再复制一次。

account_not_eligible这个账号当前不能充值这个套餐请买家换一个账号。
request_rejected请求未通过请买家核对卡密和账号后重试。
busy / service_unavailable / try_later系统繁忙或暂时不可用稍后重新核对。

POST /redeem

POST/redeem幂等锁定卡密

用核对票据提交兑换。接口立即返回订单，开通在后台进行。卡密从这一步开始锁定。

请求字段

字段类型必填说明
ticketstring是POST /redeem/verify 返回的票据。
idempotency_keystring是幂等号，8–64 位，可以使用字母、数字和 . _ : -。每次新的兑换使用新值，建议用你系统中的订单号或 UUID；同一次兑换的所有重试使用同一个值。

示例

curl -X POST {BASE}/redeem -H "Authorization: Bearer $KEY" -H "User-Agent: my-shop/1.0" \
  -H "Content-Type: application/json" \
  -d '{"ticket":"tk_3f9a1c07b2d4e5a6b7c8d9e0f1a2b3c4","idempotency_key":"order-20261005-000123"}'
{
  "ok": true,
  "data": {
    "order_no": "OD3F9A1C07B2D4E5",
    "status": "processing",
    "cdk_state": "held",
    "plan": "pro-5x",
    "plan_name": "Pro 5x",
    "buyer_email": "bu***@example.com",
    "message": "开通中，通常 1–3 分钟。请不要重复提交。卡密已锁定。",
    "created_at": "2026-10-05T09:02:11Z",
    "updated_at": "2026-10-05T09:02:11Z",
    "poll_after": 8
  },
  "trace_id": "9F2A41C07B"
}

返回的是订单对象，字段说明见 GET /orders/{order_no}。

重试规则

情况处理
请求超时、连接中断、没有收到响应，或返回 5xx用同一个 idempotency_key 和同一张 ticket 重发，返回的是同一张订单，不会重复兑换。也可以调用 POST /orders/lookup 按卡密找回订单。不要换新的幂等号，也不要重新核对后再提交。
返回 busy、too_many_inflight、service_unavailable、try_later这次提交没有执行，票据仍然有效。等待 retry_after 秒（没有时等几秒）后，用同一张票据和同一个幂等号重发。
返回其他错误，例如 wait_before_retry、ticket_expired、session_invalid、account_has_plan、cdk_used、cdk_not_usable、request_rejected票据已失效。先处理问题（等待、换账号或重新复制 Session），再从 POST /redeem/verify 重新开始，并使用新的幂等号。
返回 ticket_used这张票据已经提交过，error.details.order_no 是对应的订单，直接查询该订单。换新的幂等号也不会产生新订单。
返回 idempotency_key_reused这个幂等号已经和另一张票据一起用过，换一个新的。

GET /orders/{order_no}

GET/orders/{order_no}轮询

查询订单的当前状态。order_no 是 POST /redeem 返回的订单号。只能查询你这把密钥提交的订单，其他订单一律返回 404。

响应字段

字段类型说明
order_nostring订单号。
statusstring订单状态：processing、succeeded、failed、under_review，见 订单状态与失败处理。
cdk_statestring卡密当前的状态：available、held、used。
plan / plan_namestring套餐，取值见 POST /cdk/query。
buyer_emailstring打码后的买家账号邮箱。

failure.code / failure.actionstring只在 failed 时出现：失败原因和建议的处理方式，见 失败原因。

POST /orders/lookup

POST/orders/lookup找回订单

按卡密找回订单，用于订单号丢失、页面刷新或提交时没有收到响应的情况。返回你这把密钥对这张卡密提交的最近一张订单，格式与 GET /orders/{order_no} 相同；没有时返回 404 no_such_order。其他代理提交的订单、买家在我们网站上兑换的订单都查不到。

请求字段

字段类型必填说明

6. 订单状态与失败处理

订单状态

status含义处理
processing开通中，通常 1–3 分钟按 poll_after 继续查询，不要重复提交。卡密已锁定。
succeeded已开通（终态）提示买家到 ChatGPT 中确认。卡密已消耗。
failed失败（终态）查看 failure 和 cdk_state：cdk_state 为 available 时可以重新开始，其他情况不要重新提交，联系我们。
under_review人工核对中，通常 2 小时内有结果不要重复提交，按 poll_after（60 秒）继续查询，之后会变为 succeeded 或 failed。需要加急时联系我们并提供订单号。卡密已锁定。

卡密状态

cdk_state含义
available未消耗：卡密仍可使用，可以重新核对、重新提交。
held已锁定：正在处理或等待人工核对，不能重复提交。
used已使用：已兑换成功。

失败订单的 cdk_state 以最近一次查询为准，失败后卡密恢复为 available 可能需要几秒。

失败原因

订单为 failed 时，failure.code 是失败原因，failure.action 是建议界面如何引导买家：

failure.codefailure.action含义
session_invalidrecopy_session账号登录已失效：请买家重新复制 Session，再重新核对。
account_has_planchange_account账号已有生效中的套餐：请买家换一个账号。
account_restrictedchange_account账号暂时无法充值：过两分钟再试，或者换一个账号。
payment_blockedretry_later付款被风控拦截：过两分钟再试。
payment_failedretry_later付款没有成功：过两分钟再试。
try_laterretry_later通道暂时繁忙：过两分钟再试。
cancelledretry_later这次充值已取消。
not_acceptedretry_later这次提交没有被受理。
recharge_failedretry_later其他原因未完成。

失败后重新提交

订单为 failed 且 cdk_state 为 available 时，卡密仍可使用。按 failure.action 引导买家（等待两分钟、换一个账号或重新复制 Session），再从 POST /redeem/verify 重新开始，并使用新的幂等号。部分失败之后（例如付款被风控拦截），同一个账号需要等待约 2 分钟才能再次提交，否则会返回 wait_before_retry，响应带 retry_after。

cdk_state 不是 available 时，不要重新提交，联系我们处理。

警告

failure.action 为 retry_later 时，表示请买家过两分钟后自己再试一次，不是让你的系统过两分钟后自动提交。每次提交都会实际发起一次付款，同一个账号连续失败时，自动重交只会继续失败。重新提交必须由买家本人发起，并从 POST /redeem/verify 开始。

8. 示例代码

四份示例完成同一件事：查询卡密、核对账号、提交兑换（按 重试规则 处理超时和未执行的提交）、按 poll_after 查询到出结果。只使用语言自带的库（PHP 使用 curl 扩展），设置 AGENT_API_KEY 环境变量后即可运行。

提示

  • 接入自己的系统时，idempotency_key 要在调用 POST /redeem 之前和你自己的订单一起写入数据库，进程重启后的重试也使用它。
  • 示例用 sleep 轮询是为了便于阅读。实际系统中一般由后台任务按 poll_after 定时查询，买家页面只显示当前的 message。
  • 买家的 Session 只在本次请求中使用，不要保存，不要写进日志。

Python 3.8+，只使用标准库

"""兑换接口 v1 示例（Python 3.8+，只用标准库）。

用法：
    export AGENT_API_KEY=cpa_...          # 密钥只放在服务器的环境变量里
    python redeem.py <卡密> <买家 Session 文件>

把这份代码接进你的系统时：idempotency_key 要在调用 /redeem 之前和你自己的订单一起存进数据库，
重试时原样复用；买家的 Session 只在这一次请求里用，不要保存、不要写日志。
"""

import http.client
import json
import os
import secrets
import sys
import time
import urllib.error
import urllib.request

BASE = os.environ.get("AGENT_API_BASE", "https://recharge.chongplus.store/api/open/v1")
KEY = os.environ["AGENT_API_KEY"]
# 换成你自己系统的名字。必须设置：urllib 的默认值（Python-urllib/3.x）会被网关拒绝（HTTP 403，回包是 error code: 1010）。
USER_AGENT = "my-shop/1.0"

# 这几种错误说明「这次没处理」：等 retry_after 秒后，用同一张 ticket、同一个 idempotency_key 原样再发。
RESEND_SAME = {"busy", "rate_limited", "too_many_inflight", "service_unavailable",
               "service_disabled", "try_later", "internal_error"}
UNFINISHED = {"processing", "under_review"}


class ApiError(Exception):
    """接口明确返回了错误（ok=false）。"""

    def __init__(self, status, error, trace_id):
        super().__init__(f"{error.get('code')}: {error.get('message')} (trace_id={trace_id})")
        self.status = status
        self.code = error.get("code", "")
        self.message = error.get("message", "")
        self.retry_after = error.get("retry_after") or 0
        self.details = error.get("details") or {}


class NetworkError(Exception):
    """没拿到响应（超时、断网、网关错误页）：结果未知，只能原样重发或按卡密找回。"""


def call(method, path, body=None):
    data = None if body is None else json.dumps(body, ensure_ascii=False).encode("utf-8")
    req = urllib.request.Request(BASE + path, data=data, method=method)
    req.add_header("Authorization", "Bearer " + KEY)
    req.add_header("User-Agent", USER_AGENT)
    if data is not None:
        req.add_header("Content-Type", "application/json")
    try:
        with urllib.request.urlopen(req, timeout=90) as resp:  # 核对账号一步要 10 秒左右
            status, raw = resp.status, resp.read()
    except urllib.error.HTTPError as e:  # 4xx / 5xx 也带着 JSON
        status, raw = e.code, e.read()
    except (OSError, http.client.HTTPException) as e:  # 超时、断网、连接被断开
        raise NetworkError(str(e)) from e
    try:
        payload = json.loads(raw)
    except ValueError as e:
        raise NetworkError(f"HTTP {status}，回包不是 JSON") from e
    if payload.get("ok"):
        return payload["data"]
    raise ApiError(status, payload.get("error") or {}, payload.get("trace_id"))


def submit(ticket, idem, cdk):
    """确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。"""
    for _ in range(6):
        try:
            return call("POST", "/redeem", {"ticket": ticket, "idempotency_key": idem})
        except NetworkError:
            time.sleep(3)
        except ApiError as e:
            if e.code == "ticket_used" and e.details.get("order_no"):
                return call("GET", "/orders/" + e.details["order_no"])  # 这张 ticket 已经提交过：查那张单
            if e.code not in RESEND_SAME:
                raise  # 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
            time.sleep(e.retry_after or 3)
    # 一直没拿到明确结果：按卡密找回（可能已经受理了），不要换新的幂等号重新提交。
    return call("POST", "/orders/lookup", {"cdk": cdk})


def wait_until_done(order, deadline_seconds=2 * 3600):
    deadline = time.monotonic() + deadline_seconds
    while order["status"] in UNFINISHED:
        if time.monotonic() > deadline:
            break  # 等太久了：提示买家联系客服并给出 order_no，不要重新提交
        time.sleep(order.get("poll_after") or 8)
        try:
            order = call("GET", "/orders/" + order["order_no"])
        except NetworkError:
            time.sleep(10)
        except ApiError as e:
            if e.code not in RESEND_SAME:
                raise
            time.sleep(e.retry_after or 10)
    return order


def redeem(cdk, session):
    info = call("POST", "/cdk/query", {"cdk": cdk})  # 可选：先告诉买家是什么套餐
    print("套餐：", info["plan_name"], file=sys.stderr)

    check = call("POST", "/redeem/verify", {"cdk": cdk, "session": session})
    if not check["eligible"]:
        return {"ok": False, "message": check["message"]}  # 账号已有套餐：请买家换一个账号

    idem = "ord-" + secrets.token_hex(12)  # 实际使用时：和你的订单一起先存库，重试时原样复用
    order = wait_until_done(submit(check["ticket"], idem, cdk))
    return {
        "ok": order["status"] == "succeeded",
        "status": order["status"],
        "message": order["message"],
        "order_no": order["order_no"],
        "cdk_state": order["cdk_state"],
        "failure": order.get("failure"),
    }


if __name__ == "__main__":
    if len(sys.argv) != 3:
        sys.exit("用法：python redeem.py <卡密> <买家 Session 文件>")
    with open(sys.argv[2], encoding="utf-8") as f:
        buyer_session = f.read()
    try:
        result = redeem(sys.argv[1], buyer_session)
    except ApiError as e:
        result = {"ok": False, "code": e.code, "message": e.message, "details": e.details}
    print(json.dumps(result, ensure_ascii=False, indent=2))

async function waitUntilDone(order, deadlineMs = 2 * 3600_000) {
  const deadline = Date.now() + deadlineMs
  while (UNFINISHED.has(order.status)) {
    if (Date.now() > deadline) break // 等太久了：提示买家联系客服并给出 order_no，不要重新提交
    await sleep((order.poll_after || 8) * 1000)
    try {
      order = await call('GET', `/orders/${order.order_no}`)
    } catch (e) {
      if (!(e instanceof NetworkError) && !RESEND_SAME.has(e.code)) throw e
      await sleep((e.retryAfter || 10) * 1000)
    }
  }
  return order
}

		reader = bytes.NewReader(nil)
	}
	req, err := http.NewRequest(method, base+path, reader)
	if err != nil {
		return err
	}
	req.Header.Set("Authorization", "Bearer "+key)
	req.Header.Set("User-Agent", userAgent)
	if body != nil {
		req.Header.Set("Content-Type", "application/json")
	}
	resp, err := client.Do(req)
	if err != nil {
		return fmt.Errorf("%w: %v", ErrNetwork, err)
	}
	defer resp.Body.Close()
	var payload struct {
		OK      bool            `json:"ok"`
		Data    json.RawMessage `json:"data"`
		Error   *APIError       `json:"error"`
		TraceID string          `json:"trace_id"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&payload); err != nil {
		return fmt.Errorf("%w: HTTP %d，回包不是 JSON", ErrNetwork, resp.StatusCode)
	}
	if !payload.OK {
		e := payload.Error
		if e == nil {
			e = &APIError{Code: "internal_error"}
		}
		e.Status, e.TraceID = resp.StatusCode, payload.TraceID
		return e
	}
	if out == nil {
		return nil
	}
	return json.Unmarshal(payload.Data, out)
}

// submit 确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。
func submit(ticket, idem, cdk string) (*Order, error) {
	for i := 0; i < 6; i++ {
		var order Order
		err := call(http.MethodPost, "/redeem", map[string]string{"ticket": ticket, "idempotency_key": idem}, &order)
		if err == nil {
			return &order, nil
		}
		var apiErr *APIError
		switch {
		case errors.Is(err, ErrNetwork):
			time.Sleep(3 * time.Second)
		case errors.As(err, &apiErr) && apiErr.Code == "ticket_used" && apiErr.Details["order_no"] != "":
			// 这张 ticket 已经提交过：查那张单
			err = call(http.MethodGet, "/orders/"+apiErr.Details["order_no"], nil, &order)
			return &order, err
		case errors.As(err, &apiErr) && resendSame[apiErr.Code]:
			time.Sleep(time.Duration(max(apiErr.RetryAfter, 3)) * time.Second)
		default:
			return nil, err // 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
		}
	}
	// 一直没拿到明确结果：按卡密找回（可能已经受理了），不要换新的幂等号重新提交。
	var order Order
	err := call(http.MethodPost, "/orders/lookup", map[string]string{"cdk": cdk}, &order)
	return &order, err
}

func waitUntilDone(order *Order, deadline time.Duration) (*Order, error) {
	stop := time.Now().Add(deadline)
	for order.Status == "processing" || order.Status == "under_review" {
		if time.Now().After(stop) {
			break // 等太久了：提示买家联系客服并给出 order_no，不要重新提交
		}
		time.Sleep(time.Duration(max(order.PollAfter, 1)) * time.Second)
		var next Order
		err := call(http.MethodGet, "/orders/"+order.OrderNo, nil, &next)
		var apiErr *APIError
		switch {
		case err == nil:
			order = &next
		case errors.Is(err, ErrNetwork):
			time.Sleep(10 * time.Second)
		case errors.As(err, &apiErr) && resendSame[apiErr.Code]:
			time.Sleep(time.Duration(max(apiErr.RetryAfter, 10)) * time.Second)
		default:
			return order, err
		}
	}
	return order, nil
}

func redeem(cdk, session string) (map[string]any, error) {
	var info struct {
		PlanName string `json:"plan_name"`
	}
	if err := call(http.MethodPost, "/cdk/query", map[string]string{"cdk": cdk}, &info); err != nil {
		return nil, err
	}
	fmt.Fprintln(os.Stderr, "套餐：", info.PlanName) // 可选：先告诉买家是什么套餐

	var check struct {
		Eligible bool   `json:"eligible"`
		Ticket   string `json:"ticket"`
		Message  string `json:"message"`
	}
	if err := call(http.MethodPost, "/redeem/verify", map[string]string{"cdk": cdk, "session": session}, &check); err != nil {
		return nil, err
	}
	if !check.Eligible {
		return map[string]any{"ok": false, "message": check.Message}, nil // 账号已有套餐：请买家换一个账号
	}

	buf := make([]byte, 12)
	if _, err := rand.Read(buf); err != nil {
		return nil, err
	}
	idem := "ord-" + hex.EncodeToString(buf) // 实际使用时：和你的订单一起先存库，重试时原样复用
	order, err := submit(check.Ticket, idem, cdk)
	if err != nil {
		return nil, err
	}
	if order, err = waitUntilDone(order, 2*time.Hour); err != nil {
		return nil, err
	}
	return map[string]any{
		"ok": order.Status == "succeeded", "status": order.Status, "message": order.Message,
		"order_no": order.OrderNo, "cdk_state": order.CDKState, "failure": order.Failure,
	}, nil
}

<?php
// 兑换接口 v1 示例（PHP 7.4+，需要 curl 扩展）。
//
// 用法：
//   export AGENT_API_KEY=cpa_...          # 密钥只放在服务器的环境变量里
//   php redeem.php <卡密> <买家 Session 文件>
//
// 把这份代码接进你的系统时：idempotency_key 要在调用 /redeem 之前和你自己的订单一起存进数据库，
// 重试时原样复用；买家的 Session 只在这一次请求里用，不要保存、不要写日志。

define('API_BASE', getenv('AGENT_API_BASE') ?: 'https://recharge.chongplus.store/api/open/v1');
define('API_KEY', (string) getenv('AGENT_API_KEY'));
// 换成你自己系统的名字。别用框架或库自带的默认值：有的会被网关直接拒绝（HTTP 403，回包是 error code: 1010）。
const USER_AGENT = 'my-shop/1.0';

// 这几种错误说明「这次没处理」：等 retry_after 秒后，用同一张 ticket、同一个 idempotency_key 原样再发。
const RESEND_SAME = ['busy', 'rate_limited', 'too_many_inflight', 'service_unavailable', 'service_disabled', 'try_later', 'internal_error'];
const UNFINISHED = ['processing', 'under_review'];

/** 接口明确返回了错误（ok=false）。 */
class ApiError extends Exception
{
    public $status;
    public $errorCode;
    public $userMessage; // 给买家看的那句话
    public $retryAfter;
    public $details;

    public function __construct(int $status, array $error, string $traceId)
    {
        $this->status = $status;
        $this->errorCode = (string) ($error['code'] ?? '');
        $this->userMessage = (string) ($error['message'] ?? '');
        $this->retryAfter = (int) ($error['retry_after'] ?? 0);
        $this->details = is_array($error['details'] ?? null) ? $error['details'] : [];
        parent::__construct("{$this->errorCode}: {$this->userMessage} (trace_id={$traceId})");
    }
}

/** 没拿到响应（超时、断网、网关错误页）：结果未知，只能原样重发或按卡密找回。 */
class NetworkError extends Exception
{
}

function call(string $method, string $path, ?array $body = null): array
{
    $headers = ['Authorization: Bearer ' . API_KEY];
    $options = [
        CURLOPT_CUSTOMREQUEST => $method,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_USERAGENT => USER_AGENT,
        CURLOPT_CONNECTTIMEOUT => 10,
        CURLOPT_TIMEOUT => 90, // 核对账号一步要 10 秒左右
    ];
    if ($body !== null) {
        $options[CURLOPT_POSTFIELDS] = json_encode($body, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR);
        $headers[] = 'Content-Type: application/json';
    }
    $options[CURLOPT_HTTPHEADER] = $headers;
    $ch = curl_init(API_BASE . $path);
    curl_setopt_array($ch, $options);
    $raw = curl_exec($ch);
    $status = (int) curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    if ($raw === false) {
        throw new NetworkError(curl_error($ch)); // 超时、断网、连接被断开
    }
    $payload = json_decode($raw, true);
    if (!is_array($payload)) {
        throw new NetworkError("HTTP {$status}，回包不是 JSON");
    }
    if (!empty($payload['ok'])) {
        return $payload['data'];
    }
    throw new ApiError($status, is_array($payload['error'] ?? null) ? $payload['error'] : [], (string) ($payload['trace_id'] ?? ''));
}

/** 确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。 */
function submit(string $ticket, string $idem, string $cdk): array
{
    for ($i = 0; $i < 6; $i++) {
        try {
            return call('POST', '/redeem', ['ticket' => $ticket, 'idempotency_key' => $idem]);
        } catch (NetworkError $e) {
            sleep(3);
        } catch (ApiError $e) {
            if ($e->errorCode === 'ticket_used' && !empty($e->details['order_no'])) {
                return call('GET', '/orders/' . rawurlencode($e->details['order_no'])); // 这张 ticket 已经提交过：查那张单
            }
            if (!in_array($e->errorCode, RESEND_SAME, true)) {
                throw $e; // 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
            }
            sleep($e->retryAfter > 0 ? $e->retryAfter : 3);
        }
    }
    // 一直没拿到明确结果：按卡密找回（可能已经受理了），不要换新的幂等号重新提交。
    return call('POST', '/orders/lookup', ['cdk' => $cdk]);
}

function waitUntilDone(array $order, int $deadlineSeconds = 7200): array
{
    $deadline = time() + $deadlineSeconds;
    while (in_array($order['status'], UNFINISHED, true)) {
        if (time() > $deadline) {
            break; // 等太久了：提示买家联系客服并给出 order_no，不要重新提交
        }
        sleep(max(1, (int) ($order['poll_after'] ?? 8)));
        try {
            $order = call('GET', '/orders/' . rawurlencode($order['order_no']));
        } catch (NetworkError $e) {
            sleep(10);
        } catch (ApiError $e) {
            if (!in_array($e->errorCode, RESEND_SAME, true)) {
                throw $e;
            }
            sleep($e->retryAfter > 0 ? $e->retryAfter : 10);
        }
    }
    return $order;
}

function redeem(string $cdk, string $session): array
{
    $info = call('POST', '/cdk/query', ['cdk' => $cdk]); // 可选：先告诉买家是什么套餐
    error_log('套餐：' . $info['plan_name']);

    $check = call('POST', '/redeem/verify', ['cdk' => $cdk, 'session' => $session]);
    if (empty($check['eligible'])) {
        return ['ok' => false, 'message' => $check['message']]; // 账号已有套餐：请买家换一个账号
    }

    $idem = 'ord-' . bin2hex(random_bytes(12)); // 实际使用时：和你的订单一起先存库，重试时原样复用
    $order = waitUntilDone(submit($check['ticket'], $idem, $cdk));
    return [
        'ok' => $order['status'] === 'succeeded',
        'status' => $order['status'],
        'message' => $order['message'],
        'order_no' => $order['order_no'],
        'cdk_state' => $order['cdk_state'],
        'failure' => $order['failure'] ?? null,
    ];
}

9. 联调与上线检查

联调步骤

  1. 调用 GET /ping，确认密钥有效，返回的 ip 就是你服务器的出口 IP。
  2. 向我们申请一张测试卡密，用 POST /cdk/query 查询一次，确认能看到套餐。
  3. 准备一个没有生效中套餐的测试账号，完整走一遍核对账号、提交兑换、查询订单，直到看到 succeeded。没有沙箱环境，测试兑换会实际开通并用掉这张测试卡密。
  4. 验证常见的错误分支：卡密写错（cdk_invalid）、Session 只复制了一部分（session_format）、同一个幂等号连续提交两次（返回同一张订单）、账号已有套餐（eligible 为 false）。

上线前检查

  • 密钥只在服务器的环境变量里，没有出现在前端代码、日志和聊天记录中。
  • GET /ping 返回的来源 IP 与登记的出口 IP 一致。
  • 所有请求的超时不少于 60 秒，核对账号一步不会因为耗时长被当成失败。
  • 请求带的是自己系统的 User-Agent，不是语言自带的默认值。
  • 一次兑换只生成一个幂等号，所有重试都复用它；超时后不重新核对，也不换幂等号。
  • 轮询间隔不短于 poll_after，并设有总的等待上限（例如 2 小时）；超过上限时提示买家联系客服，并给出 order_no。
  • 买家的 Session 不入库、不进日志；你的日志里只记录 order_no 和 trace_id。
  • 买家界面直接显示 message，失败时按 failure.action 引导买家。
  • 订单失败后，只有买家本人点了重试才重新核对、重新提交，程序里没有任何自动重交。
  • 收到 429、503 时按 Retry-After 等待后再试，不立即重试。
  • 联调步骤中的错误分支都已验证，界面上的提示与本文档一致。

10. 常见问题

核对账号为什么需要 10 秒左右？
这一步要实时校验买家的账号，属于正常耗时。请把超时设长，并在界面上提示买家正在核对账号。
买家连续点了两次确认兑换会怎样？
一张票据只能使用一次：同一个幂等号的第二次请求返回同一张订单，换了幂等号的第二次请求返回 ticket_used，不会重复兑换。
订单一直是 processing 怎么办？
通常 1–3 分钟出结果。超过 10 分钟时继续按 poll_after 查询；超过 2 小时请联系我们并提供 order_no。不要重新提交。
买家想用另一个账号兑换同一张卡密？
只要卡密仍是 available（核对没有通过，或兑换失败后卡密已恢复），就可以用新的账号重新调用 POST /redeem/verify。
收到 403，但响应不是 JSON？
响应是一行 error code: 1010 时，请求在网关就被拒绝了，原因是 User-Agent（见 通用约定），与密钥和 IP 无关，换成你自己系统的名称即可。密钥或 IP 的问题，响应都是 JSON（invalid_key、ip_not_allowed）。
失败后能让程序过两分钟自动重新提交吗？
不能。每次提交都会实际发起一次付款，同一个账号连续失败时，自动重交只会继续失败。请把 message 显示给买家，由买家决定换一个账号，还是稍后自己再试。
联系我们时需要提供什么？
order_no（或响应中的 trace_id）、出问题的大致时间、卡密的前 8 位和后 4 位，以及你收到的完整响应（请去掉密钥）。
