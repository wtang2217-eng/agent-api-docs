1. 流程总览

一次兑换是四步，每一步都是你的服务器向我们发一个 HTTPS 请求：

  1. 查卡密（可选）

    买家粘贴卡密后，调用 POST /cdk/query，告诉买家这是什么套餐、能不能用。不消耗卡密。

  2. 核对账号

    买家粘贴自己的 ChatGPT 账号信息（Session）后，调用 POST /redeem/verify。约 10 秒，通过后拿到一张 ticket（核对票据，10 分钟内有效）。

  3. 确认兑换

    买家点「确认兑换」，调用 POST /redeem，带上 ticket 和你生成的 idempotency_key（幂等号），拿到订单号 order_no。

  4. 查订单直到出结果

    按返回的 poll_after 秒轮询 GET /orders/{order_no}，直到 status 变成 succeeded（已开通）或 failed（失败）。通常 1–3 分钟。

最重要的一条

网络超时、没拿到响应的时候，用同一个 idempotency_key 原样再发一次（或用 POST /orders/lookup 找回订单），绝不会重复兑换；不要换新的幂等号、也不要重新核对再提交。细则见 POST /redeem。

2. 开始之前

我们会给你三样东西：

项目说明
接口地址https://recharge.chongplus.store/api/open/v1（下文简写 {BASE}）
API 密钥cpa_ 开头、共 47 个字符。只在创建时显示一次，我们这边只存指纹，丢了只能停用后重发。
来源 IP 登记把你服务器的出口 IP（或 IP 段）告诉我们。登记后，这把密钥只有从这些 IP 发来的请求才有效。不知道出口 IP 的话：用 GET /ping 可以看到我们看到的你的来源 IP；如果密钥已经限了 IP，被拒绝的回包（ip_not_allowed）里的 error.details.ip 也是我们看到的你的来源 IP。

另附一份 OpenAPI 3.0 格式的接口描述文件 openapi.json：可以直接导入 Apifox、Postman 这类工具，自动生成全部接口、请求示例和数据结构；里面的字段、取值、错误码和本文档完全一致。

安全规则（请务必遵守）
  • 密钥只放在你的服务器上（环境变量 / 密钥管理）。不要写进网页、手机 App 或任何前端代码，也不要贴到聊天群、工单里。
  • 接口只接受服务器对服务器的调用。浏览器里直接调用会被拒绝（我们不放行任何跨域请求）。
  • 只用 https:// 调用。用 http:// 的话密钥在路上是明文，等于已经泄露，请马上联系我们停用、换一把新的。
  • 买家的 Session 等同于账号登录凭证：只在请求里传这一次，不要保存、不要写进日志。
  • 怀疑密钥泄露：马上联系我们停用，停用立即生效，我们会发新的。
  • 用错误的密钥、或从没登记的 IP 反复请求，我们会临时封锁该来源 IP 10 分钟。

使用约定

使用本接口，即表示同意下面几条：

  • 本接口只提供兑换能力。买家看到的页面、文案和样式，由你自己设计、自己制作。
  • 不得复制、仿制或套用我们网站的页面、样式、图片、视频和教程；不得用 iframe 嵌入我们的网站，也不得用自己的域名转发（镜像）我们的网站。
  • 失败的订单只能由买家自己点重试，你的程序不得自动重新提交（原因见 状态与失败处理）。
  • 密钥只给你自己的系统用，不转借、不转卖。
  • 订单结果以本接口返回的为准。
  • 违反以上任何一条，我们会停用密钥。

联调步骤

  1. 调 GET /ping：确认密钥有效，返回的 ip 就是你服务器的出口 IP。
  2. 向我们要一张测试卡密，用 POST /cdk/query 查一次，看到套餐。
  3. 准备一个没有生效中套餐的测试账号，走一遍 核对账号 → 确认兑换 → 查订单，直到看到 succeeded。没有沙箱环境：测试兑换会真实开通、真实用掉这张测试卡密。
  4. 把常见的错误走一遍：卡密写错（cdk_invalid）、Session 只复制了一半（session_format）、同一个幂等号连发两次（拿到同一张订单）、已有套餐的账号（eligible: false）。
  5. 对照 上线前自检 逐条确认。

3. 通用约定

请求

  • HTTPS，JSON（UTF-8）。POST 请求带 Content-Type: application/json。请求体不超过 128 KB（核对账号一步最大，其他接口的请求体都很小）。
  • 认证：每个请求都带 Authorization: Bearer <你的密钥>。
  • 每个请求带一个 User-Agent，写你自己系统的名字（比如 my-shop/1.0）。有些语言或库自带的默认值会被网关直接拒绝（比如 Python 的 urllib 和 pycurl、Java 8 及更早的版本、Perl 的 LWP）。被拒时是 HTTP 403、回包只有一行纯文本 error code: 1010（不是 JSON），请求没有到达接口。
  • 请求超时请设 60 秒以上（核对账号一步要 10 秒左右）。

响应

成功（HTTP 200）：

{
  "ok": true,
  "data": { ... },
  "trace_id": "9F2A41C07B"
}

失败：

{
  "ok": false,
  "error": {
    "code": "cdk_used",
    "message": "卡密已兑换或已使用",
    "retryable": false,
    "cdk_state": "used",
    "details": { "order_no": "OD3F9A1C07B2D4E5" }
  },
  "trace_id": "9F2A41C07B"
}
字段说明
error.code错误代号，稳定不变，用它写判断。全部代号见 错误码总表。
error.message给终端买家看的中文句子，可以直接显示；想自己写文案就按 code 判断。
error.retryable同样的操作稍后能不能再做一次。怎么重来以各接口的说明为准（有的要重新核对账号）。
error.retry_after建议等多少秒再试；同时放在 Retry-After 响应头里。只在需要等的错误里出现。
error.cdk_state这一步之后卡密是什么状态：available 还没消耗 / held 已锁定 / used 已使用。不一定出现。
error.details可能带两种信息，都不一定出现：order_no——卡密已被用或正在处理、而且正是你这把密钥提交的订单时，告诉你订单号，用 GET /orders/{order_no} 去查；ip——来源 IP 被拒绝（ip_not_allowed）时，本站看到的你的来源 IP。
trace_id每个响应都有。联系我们排查问题时请带上它。

HTTP 状态码

状态码含义
200成功（ok: true）。
400请求格式不对（bad_request），或 Session 格式不对（session_format）。
401 / 403密钥无效或已停用（invalid_key）/ 来源 IP 不在登记的名单里（ip_not_allowed）。
404接口、核对票据或订单不存在。
409当前状态不允许这个操作：卡密已用、核对已过期、票据已用过、账号要等一等……
422请求没问题但内容过不了：卡密无效、Session 失效。
429请求太频繁 / 同时处理的订单太多 / 系统繁忙。按 Retry-After 等。
500 / 503我们这边暂时处理不了，稍后重试。

限额

  • 每把密钥有「每分钟请求数」和「同时处理的订单数」两个上限（默认 60 次/分钟、5 单；实际数值以 GET /ping 返回的 limits 为准，需要调整联系我们）。超了返回 429（rate_limited / too_many_inflight）。
  • 所有代理共用一部分处理能力，每把密钥最多占其中的一部分。高峰时、或者你这把密钥发得太密时，可能临时返回 429 busy：按 Retry-After 稍后重试即可，不是你的密钥有问题。

时间格式

所有时间都是 RFC 3339 的 UTC 时间，例如 2026-10-05T09:00:00Z。

POST/cdk/query

出了问题怎么重来（务必读完）

你遇到的情况怎么做
请求超时、断网、没拿到响应，或收到 5xx用同一个 idempotency_key、同一张 ticket 原样再发一次，会返回同一张订单，不会重复兑换。也可以用 POST /orders/lookup 按卡密找回订单。不要换新的幂等号，不要重新核对后再提交。
返回「没送出去」类错误：busy、too_many_inflight、service_unavailable、try_later这次提交没有发生，票据还能用。等 retry_after 秒（没有就等几秒）后，用同一张票据、同一个幂等号原样再发。
返回其他错误：wait_before_retry、ticket_expired、session_invalid、account_has_plan、cdk_used、cdk_not_usable、request_rejected……这张票据已作废。先处理问题（等一等 / 换账号 / 重新复制 Session），再从 /redeem/verify 重新来，并用新的幂等号。
ticket_used这张票据已经提交过了，error.details.order_no 就是对应订单，去查它。换新的幂等号不会得到新订单。
idempotency_key_reused这个幂等号已经和另一张票据一起用过。换一个新的。

5. 状态与失败处理

订单状态 status

status含义你该怎么做
processing开通中（通常 1–3 分钟）按 poll_after 继续查；不要重复提交。卡密已锁定。
succeeded已开通（终态）告诉买家去 ChatGPT 里确认。卡密已消耗。
failed失败（终态）看 failure 和 cdk_state：available 可以重新来；其他情况不要重新提交，联系我们。
under_review需要人工核对（通常 2 小时内有结果）不要重复提交；继续按 poll_after（60 秒）查，它之后会变成 succeeded 或 failed；着急就联系我们并提供订单号。卡密已锁定。

卡密状态 cdk_state

cdk_state含义
available还没消耗：卡密还在，可以重新核对、重新提交。
held已锁定：正在处理或等人工核对，不能重复提交。
used已使用：已经兑换成功。

失败订单的 cdk_state 以最近一次查询为准：失败后卡密恢复成 available 可能要等几秒。

失败原因 failure.code 与建议动作 failure.action

failure.codeaction含义
session_invalidrecopy_session账号登录已失效：请买家重新复制 Session，再重新核对。
account_has_planchange_account账号已有生效中的套餐：请买家换一个账号。

payment_failedretry_later付款没有成功：过两分钟再试。

not_acceptedretry_later这次提交没有被受理。

失败之后怎么重来

订单 failed 且 cdk_state 是 available：卡密还在。按 action 引导买家（等两分钟 / 换账号 / 重新复制 Session），然后从 /redeem/verify 重新来，使用新的幂等号。部分失败（比如付款被风控拦截）之后，同一个账号需要等约 2 分钟才能再次提交，否则会收到 wait_before_retry（带 retry_after）。

cdk_state 不是 available 时，不要重新提交，联系我们。

不要让程序自动重新提交

failure.action 是 retry_later 时，意思是请买家过两分钟再自己点一次，不是让你的系统过两分钟自动再交。每一次提交都会真实发起一次付款；同一个账号接连失败时，自动重交只会接着失败。重新提交必须由买家自己发起，并且从 /redeem/verify 重新核对开始。

7. 示例代码

下面四份示例做的是同一件事：查卡密 → 核对账号 → 确认兑换（按 出了问题怎么重来 处理超时和「这次没处理」的错误）→ 按 poll_after 查到出结果。都只用语言自带的库（PHP 用 curl 扩展），设好 AGENT_API_KEY 环境变量就能运行；每次更新文档，我们都会把四份示例对着接口逐个跑一遍。

接进你自己的系统时
  • idempotency_key 要在调用 /redeem 之前和你自己的订单一起存进数据库；进程重启以后的重试也用它。
  • 示例用 sleep 轮询是为了好读。在你的系统里通常是后台任务按 poll_after 定时去查，买家页面只显示当前的 message。
  • 买家的 Session 只在这一次请求里用，不要保存、不要写日志。

class ApiError(Exception):
    """接口明确返回了错误（ok=false）。"""

    def __init__(self, status, error, trace_id):
        super().__init__(f"{error.get('code')}: {error.get('message')} (trace_id={trace_id})")
        self.status = status
        self.code = error.get("code", "")
        self.message = error.get("message", "")
        self.retry_after = error.get("retry_after") or 0
        self.details = error.get("details") or {}


class NetworkError(Exception):
    """没拿到响应（超时、断网、网关错误页）：结果未知，只能原样重发或按卡密找回。"""


def call(method, path, body=None):
    data = None if body is None else json.dumps(body, ensure_ascii=False).encode("utf-8")
    req = urllib.request.Request(BASE + path, data=data, method=method)
    req.add_header("Authorization", "Bearer " + KEY)
    req.add_header("User-Agent", USER_AGENT)
    if data is not None:
        req.add_header("Content-Type", "application/json")
    try:
        with urllib.request.urlopen(req, timeout=90) as resp:  # 核对账号一步要 10 秒左右
            status, raw = resp.status, resp.read()
    except urllib.error.HTTPError as e:  # 4xx / 5xx 也带着 JSON
        status, raw = e.code, e.read()
    except (OSError, http.client.HTTPException) as e:  # 超时、断网、连接被断开
        raise NetworkError(str(e)) from e
    try:
        payload = json.loads(raw)
    except ValueError as e:
        raise NetworkError(f"HTTP {status}，回包不是 JSON") from e
    if payload.get("ok"):
        return payload["data"]
    raise ApiError(status, payload.get("error") or {}, payload.get("trace_id"))


def submit(ticket, idem, cdk):
    """确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。"""
    for _ in range(6):
        try:
            return call("POST", "/redeem", {"ticket": ticket, "idempotency_key": idem})
        except NetworkError:
            time.sleep(3)
        except ApiError as e:
            if e.code == "ticket_used" and e.details.get("order_no"):
                return call("GET", "/orders/" + e.details["order_no"])  # 这张 ticket 已经提交过：查那张单
            if e.code not in RESEND_SAME:
                raise  # 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
            time.sleep(e.retry_after or 3)
    # 一直没拿到明确结果：按卡密找回（可能已经受理了），绝不换新的幂等号重新提交。
    return call("POST", "/orders/lookup", {"cdk": cdk})


def wait_until_done(order, deadline_seconds=2 * 3600):
    deadline = time.monotonic() + deadline_seconds
    while order["status"] in UNFINISHED:
        if time.monotonic() > deadline:
            break  # 等太久了：提示买家联系客服并给出 order_no，不要重新提交
        time.sleep(order.get("poll_after") or 8)
        try:
            order = call("GET", "/orders/" + order["order_no"])
        except NetworkError:
            time.sleep(10)
        except ApiError as e:
            if e.code not in RESEND_SAME:
                raise
            time.sleep(e.retry_after or 10)
    return order


def redeem(cdk, session):
    info = call("POST", "/cdk/query", {"cdk": cdk})  # 可选：先告诉买家是什么套餐
    print("套餐：", info["plan_name"], file=sys.stderr)

    if not check["eligible"]:
        return {"ok": False, "message": check["message"]}  # 账号已有套餐：请买家换一个账号

    idem = "ord-" + secrets.token_hex(12)  # 实际使用时：和你的订单一起先存库，重试时原样复用

        "ok": order["status"] == "succeeded",

        "message": order["message"],
        "order_no": order["order_no"],
        "cdk_state": order["cdk_state"],

    }

func (e *APIError) Error() string {

// ErrNetwork 没拿到响应（超时、断网、网关错误页）：结果未知，只能原样重发或按卡密找回。
var ErrNetwork = errors.New("network error")

// Order 一张订单（只列了这里用到的字段）。
type Order struct {
	OrderNo   string `json:"order_no"`
	Status    string `json:"status"`
	CDKState  string `json:"cdk_state"`
	Message   string `json:"message"`
	PollAfter int    `json:"poll_after"`
	Failure   *struct {
		Code   string `json:"code"`
		Action string `json:"action"`
	} `json:"failure,omitempty"`

func call(method, path string, body, out any) error {
	var reader *bytes.Reader
	if body != nil {
		raw, err := json.Marshal(body)
		if err != nil {
			return err
		}
		reader = bytes.NewReader(raw)
	} else {
		reader = bytes.NewReader(nil)
	}
	req, err := http.NewRequest(method, base+path, reader)
	if err != nil {
		return err
	}
	req.Header.Set("Authorization", "Bearer "+key)
	req.Header.Set("User-Agent", userAgent)
	if body != nil {
		req.Header.Set("Content-Type", "application/json")
	}
	resp, err := client.Do(req)
	if err != nil {
		return fmt.Errorf("%w: %v", ErrNetwork, err)
	}
	defer resp.Body.Close()
	var payload struct {
		OK      bool            `json:"ok"`
		Data    json.RawMessage `json:"data"`
		Error   *APIError       `json:"error"`
		TraceID string          `json:"trace_id"`
	}
	if err := json.NewDecoder(resp.Body).Decode(&payload); err != nil {
		return fmt.Errorf("%w: HTTP %d，回包不是 JSON", ErrNetwork, resp.StatusCode)
	}
	if !payload.OK {
		e := payload.Error
		if e == nil {
			e = &APIError{Code: "internal_error"}
		}
		e.Status, e.TraceID = resp.StatusCode, payload.TraceID
		return e
	}
	if out == nil {
		return nil
	}
	return json.Unmarshal(payload.Data, out)
}

// submit 确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。
func submit(ticket, idem, cdk string) (*Order, error) {
	for i := 0; i < 6; i++ {
		var order Order
		err := call(http.MethodPost, "/redeem", map[string]string{"ticket": ticket, "idempotency_key": idem}, &order)
		if err == nil {
			return &order, nil
		}
		var apiErr *APIError
		switch {
		case errors.Is(err, ErrNetwork):
			time.Sleep(3 * time.Second)
		case errors.As(err, &apiErr) && apiErr.Code == "ticket_used" && apiErr.Details["order_no"] != "":
			// 这张 ticket 已经提交过：查那张单
			err = call(http.MethodGet, "/orders/"+apiErr.Details["order_no"], nil, &order)
			return &order, err
		case errors.As(err, &apiErr) && resendSame[apiErr.Code]:
			time.Sleep(time.Duration(max(apiErr.RetryAfter, 3)) * time.Second)
		default:
			return nil, err // 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
		}
	}
	// 一直没拿到明确结果：按卡密找回（可能已经受理了），绝不换新的幂等号重新提交。
	var order Order
	err := call(http.MethodPost, "/orders/lookup", map[string]string{"cdk": cdk}, &order)
	return &order, err
}

func waitUntilDone(order *Order, deadline time.Duration) (*Order, error) {
	stop := time.Now().Add(deadline)
	for order.Status == "processing" || order.Status == "under_review" {
		if time.Now().After(stop) {
			break // 等太久了：提示买家联系客服并给出 order_no，不要重新提交
		}
		time.Sleep(time.Duration(max(order.PollAfter, 1)) * time.Second)
		var next Order
		err := call(http.MethodGet, "/orders/"+order.OrderNo, nil, &next)
		var apiErr *APIError
		switch {
		case err == nil:
			order = &next
		case errors.Is(err, ErrNetwork):
			time.Sleep(10 * time.Second)
		case errors.As(err, &apiErr) && resendSame[apiErr.Code]:
			time.Sleep(time.Duration(max(apiErr.RetryAfter, 10)) * time.Second)
		default:
			return order, err
		}
	}
	return order, nil
}

func redeem(cdk, session string) (map[string]any, error) {
	var info struct {
		PlanName string `json:"plan_name"`
	}
	if err := call(http.MethodPost, "/cdk/query", map[string]string{"cdk": cdk}, &info); err != nil {
		return nil, err
	}
	fmt.Fprintln(os.Stderr, "套餐：", info.PlanName) // 可选：先告诉买家是什么套餐

	var check struct {
		Eligible bool   `json:"eligible"`
		Ticket   string `json:"ticket"`
		Message  string `json:"message"`
	}
	if err := call(http.MethodPost, "/redeem/verify", map[string]string{"cdk": cdk, "session": session}, &check); err != nil {
		return nil, err
	}
	if !check.Eligible {
		return map[string]any{"ok": false, "message": check.Message}, nil // 账号已有套餐：请买家换一个账号
	}

	buf := make([]byte, 12)
	if _, err := rand.Read(buf); err != nil {
		return nil, err
	}
	idem := "ord-" + hex.EncodeToString(buf) // 实际使用时：和你的订单一起先存库，重试时原样复用
	order, err := submit(check.Ticket, idem, cdk)
	if err != nil {
		return nil, err
	}
	if order, err = waitUntilDone(order, 2*time.Hour); err != nil {
		return nil, err
	}
	return map[string]any{
		"ok": order.Status == "succeeded", "status": order.Status, "message": order.Message,
		"order_no": order.OrderNo, "cdk_state": order.CDKState, "failure": order.Failure,
	}, nil
}

	}

}

PHP 7.4+（redeem.php，需要 curl 扩展） 
<?php
// 兑换接口 v1 示例（PHP 7.4+，需要 curl 扩展）。
//
// 用法：
//   export AGENT_API_KEY=cpa_...          # 密钥只放在服务器的环境变量里
//   php redeem.php <卡密> <买家 Session 文件>
//
// 把这份代码接进你的系统时：idempotency_key 要在调用 /redeem 之前和你自己的订单一起存进数据库，
// 重试时原样复用；买家的 Session 只在这一次请求里用，不要保存、不要写日志。

define('API_BASE', getenv('AGENT_API_BASE') ?: 'https://recharge.chongplus.store/api/open/v1');
define('API_KEY', (string) getenv('AGENT_API_KEY'));
// 换成你自己系统的名字。别用框架或库自带的默认值：有的会被网关直接拒绝（HTTP 403，回包是 error code: 1010）。
const USER_AGENT = 'my-shop/1.0';

// 这几种错误说明「这次没处理」：等 retry_after 秒后，用同一张 ticket、同一个 idempotency_key 原样再发。
const RESEND_SAME = ['busy', 'rate_limited', 'too_many_inflight', 'service_unavailable', 'service_disabled', 'try_later', 'internal_error'];
const UNFINISHED = ['processing', 'under_review'];

/** 接口明确返回了错误（ok=false）。 */
class ApiError extends Exception
{
    public $status;
    public $errorCode;
    public $userMessage; // 给买家看的那句话
    public $retryAfter;
    public $details;

    public function __construct(int $status, array $error, string $traceId)
    {
        $this->status = $status;
        $this->errorCode = (string) ($error['code'] ?? '');
        $this->userMessage = (string) ($error['message'] ?? '');
        $this->retryAfter = (int) ($error['retry_after'] ?? 0);
        $this->details = is_array($error['details'] ?? null) ? $error['details'] : [];
        parent::__construct("{$this->errorCode}: {$this->userMessage} (trace_id={$traceId})");
    }
}

/** 没拿到响应（超时、断网、网关错误页）：结果未知，只能原样重发或按卡密找回。 */
class NetworkError extends Exception
{
}

function call(string $method, string $path, ?array $body = null): array
{
    $headers = ['Authorization: Bearer ' . API_KEY];
    $options = [
        CURLOPT_CUSTOMREQUEST => $method,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_USERAGENT => USER_AGENT,
        CURLOPT_CONNECTTIMEOUT => 10,
        CURLOPT_TIMEOUT => 90, // 核对账号一步要 10 秒左右
    ];
    if ($body !== null) {
        $options[CURLOPT_POSTFIELDS] = json_encode($body, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR);
        $headers[] = 'Content-Type: application/json';
    }
    $options[CURLOPT_HTTPHEADER] = $headers;
    $ch = curl_init(API_BASE . $path);
    curl_setopt_array($ch, $options);
    $raw = curl_exec($ch);
    $status = (int) curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    if ($raw === false) {
        throw new NetworkError(curl_error($ch)); // 超时、断网、连接被断开
    }
    $payload = json_decode($raw, true);
    if (!is_array($payload)) {
        throw new NetworkError("HTTP {$status}，回包不是 JSON");
    }
    if (!empty($payload['ok'])) {
        return $payload['data'];
    }
    throw new ApiError($status, is_array($payload['error'] ?? null) ? $payload['error'] : [], (string) ($payload['trace_id'] ?? ''));
}

/** 确认兑换。网络出错、或者是「这次没处理」的错误，都用同一张 ticket、同一个幂等号原样再发。 */
function submit(string $ticket, string $idem, string $cdk): array
{
    for ($i = 0; $i < 6; $i++) {
        try {
            return call('POST', '/redeem', ['ticket' => $ticket, 'idempotency_key' => $idem]);
        } catch (NetworkError $e) {
            sleep(3);
        } catch (ApiError $e) {
            if ($e->errorCode === 'ticket_used' && !empty($e->details['order_no'])) {
                return call('GET', '/orders/' . rawurlencode($e->details['order_no'])); // 这张 ticket 已经提交过：查那张单
            }
            if (!in_array($e->errorCode, RESEND_SAME, true)) {
                throw $e; // 其他错误：这张 ticket 作废，处理完问题后从核对账号重新来，并换新的幂等号
            }
            sleep($e->retryAfter > 0 ? $e->retryAfter : 3);
        }
    }
    // 一直没拿到明确结果：按卡密找回（可能已经受理了），绝不换新的幂等号重新提交。
    return call('POST', '/orders/lookup', ['cdk' => $cdk]);
}

function waitUntilDone(array $order, int $deadlineSeconds = 7200): array
{
    $deadline = time() + $deadlineSeconds;
    while (in_array($order['status'], UNFINISHED, true)) {
        if (time() > $deadline) {
            break; // 等太久了：提示买家联系客服并给出 order_no，不要重新提交
        }
        sleep(max(1, (int) ($order['poll_after'] ?? 8)));
        try {
            $order = call('GET', '/orders/' . rawurlencode($order['order_no']));
        } catch (NetworkError $e) {
            sleep(10);
        } catch (ApiError $e) {
            if (!in_array($e->errorCode, RESEND_SAME, true)) {
                throw $e;
            }
            sleep($e->retryAfter > 0 ? $e->retryAfter : 10);
        }
    }
    return $order;
}

function redeem(string $cdk, string $session): array
{
    $info = call('POST', '/cdk/query', ['cdk' => $cdk]); // 可选：先告诉买家是什么套餐
    error_log('套餐：' . $info['plan_name']);

    $check = call('POST', '/redeem/verify', ['cdk' => $cdk, 'session' => $session]);
    if (empty($check['eligible'])) {
        return ['ok' => false, 'message' => $check['message']]; // 账号已有套餐：请买家换一个账号
    }

    $idem = 'ord-' . bin2hex(random_bytes(12)); // 实际使用时：和你的订单一起先存库，重试时原样复用
    $order = waitUntilDone(submit($check['ticket'], $idem, $cdk));
    return [
        'ok' => $order['status'] === 'succeeded',
        'status' => $order['status'],
        'message' => $order['message'],
        'order_no' => $order['order_no'],
        'cdk_state' => $order['cdk_state'],
        'failure' => $order['failure'] ?? null,
    ];
}

    echo json_encode($result, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT), PHP_EOL;
}

8. 上线前自检

  • 密钥只在服务器的环境变量里，没有出现在前端、日志、聊天记录里。
  • 用 GET /ping 确认「我们看到的来源 IP」就是你登记的出口 IP。
  • 所有请求的超时 ≥ 60 秒；核对账号一步不要因为慢就当成失败。
  • 请求带的是你自己系统的 User-Agent，不是语言自带的默认值。
  • 一次兑换尝试只生成一个幂等号，所有重试复用它；超时的时候不重新核对、不换幂等号。
  • 轮询间隔不短于 poll_after；设一个总的等待上限（比如 2 小时），超了提示买家联系客服并给出 order_no。
  • 买家的 Session 不落库、不进日志；你自己的日志里只记 order_no、trace_id。
  • 买家界面直接显示 message；失败时按 failure.action 引导买家。
  • 订单失败后，只有买家自己点了重试才重新核对、重新提交；程序里没有任何自动重交。
  • 收到 429 / 503 会按 Retry-After 退避，而不是立刻重试。
  • 联调步骤里的几个错误分支都走过一遍，界面上给买家的提示和本文档一致。

9. 常见问题

核对账号为什么要 10 秒？

要实时校验买家的账号，这是正常的耗时。请把超时设长，界面上给买家一个「正在核对账号」的提示。

买家点了两次「确认兑换」会怎样？

一张票据只能用一次：同一个幂等号的第二次请求返回同一张订单；换了幂等号的第二次请求返回 ticket_used。不会重复兑换。

订单一直是 processing 怎么办？

通常 1–3 分钟出结果。超过 10 分钟请继续等并按 poll_after 查；超过 2 小时联系我们，并提供 order_no。不要重新提交。

买家想换一个账号重新兑换同一张卡密？

只要卡密还是 available（核对没通过、或兑换失败后卡密恢复），就可以用新的账号重新 /redeem/verify。

收到 403，回包却不是 JSON？

回包是一行 error code: 1010：请求在网关就被拒绝了，原因是 User-Agent（见「通用约定」），和密钥、IP 无关，换成你自己系统的名字就好。密钥或 IP 的问题，回包都是 JSON（invalid_key、ip_not_allowed）。

失败了，能让程序过两分钟自动再交吗？

不能。每一次提交都会真实发起一次付款，同一个账号接连失败时，自动重交只会接着失败。请把 message 显示给买家，由买家决定换一个账号，还是过一会儿自己再点一次。

联系我们时需要提供什么？

order_no（或响应里的 trace_id）、发生的大致时间、卡密的前 8 位和后 4 位、你收到的完整响应（请去掉密钥）。
